# 파일만 올리면 GitHub 자동 업데이트

**기존 BNS 런처 v1.4.1을 다시 만들 필요가 없습니다.** 원래의 업데이트 URL
`https://github.com/seung1242at/UP/releases/latest/download/manifest.json`
을 그대로 사용합니다.

## 파일 업로드

1. [updates 폴더](https://github.com/seung1242at/UP/tree/main/updates)를 엽니다.
2. 사용자 컴퓨터의 게임 파일이 저장될 경로와 동일한 폴더로 이동합니다.
3. **Add file → Upload files → Commit changes**를 누릅니다.
4. [Actions](https://github.com/seung1242at/UP/actions)에서 **BNS auto-publish patch** 성공 여부를 봅니다.
5. [Releases](https://github.com/seung1242at/UP/releases)에 `patch-...` 버전이 생성되면 끝입니다.

예시: GitHub `updates/bin64/sample.dll` → PC `게임폴더/bin64/sample.dll`

예시: GitHub `updates/contents/Local/NCSoft/data/xml64.dat` → PC `게임폴더/contents/Local/NCSoft/data/xml64.dat`

경로는 사용 중인 게임 클라이언트의 **실제 상대 경로**를 그대로 사용해야 합니다. 예시의 `NCSoft`는 실제 경로와 다를 수 있습니다.

GitHub 안에 해당 폴더가 없다면 Add file → Create new file에서 `bin64/.gitkeep`을 저장하여 폴더를 만든 다음, 그 폴더로 이동해서 파일을 업로드할 수 있습니다. GitHub 웹 UI에서는 폴더째 드래그하여 업로드하는 것도 지원합니다.

## 같은 파일을 수정할 때

원래 위치에 있는 파일을 **같은 이름으로 수정 또는 교체**하세요. GitHub가 기존 패치 파일 전체를 누적한 새 릴리스로 자동 게시합니다. 수동으로 `manifest.json`을 만들거나 Release를 누를 필요가 없습니다.

## 런처에서

게임이 설치된 사용자가 런처를 켜면 최신 업데이트를 **자동 확인**합니다. 새로운 파일이 있으면 **업데이트 버튼**을 누를 때 다운로드 및 설치합니다. 다운로드된 파일은 경로 및 SHA-256 검증을 거쳐 교체됩니다.

## 꼭 확인할 사항

- 이 GitHub 저장소는 공개되어 있습니다. 배포 권한이 없는 게임 데이터나 계정 정보를 업로드하지 마세요.
- `ClientConfiguration.xml`, `launcher_config.json`, `client_version.txt`, `BNS_Launcher.exe`는 업로드 패치에서 자동 차단합니다.
- GitHub 웹 업로드에는 파일 크기 제한이 있습니다. 대형 DAT/UPK에는 다른 배포 경로가 필요할 수 있습니다.
- 파일을 한번에 올리고 하나의 커밋으로 저장하면 릴리스가 덜 복잡해집니다.
- 게임 파일 **삭제 동기화** 기능은 없습니다. 업로드된 새 파일/변경 파일의 복사 및 교체만 지원합니다.
- 자동 릴리스가 실패하면 Actions의 작업 로그에서 이유를 확인해야 합니다.
